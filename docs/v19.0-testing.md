# Lighttpd PHP FastCGI 19.0 testing

## Scope and source decision

Lighttpd PHP FastCGI 19.0 uses Debian 13 Trixie packages for Lighttpd,
PHP-FPM, MariaDB, Adminer and the PHP MariaDB client. Trixie supplies the
complete identity-defining stack, so this appliance needs no upstream package
repository or downloaded application artifact. Webmin and its MariaDB and PHP
modules continue to come from the signed TurnKey Trixie repository.

The acceptance command is:

```sh
/sandboxed-git/turnkey/tools/test-v19-appliance lighttpd-php-fastcgi \
    --source /home/agent/.local/worktrees/turnkey-apps/lighttpd-php-fastcgi/wish-lighttpd-php-fastcgi-v19-trixie
```

It builds a Trixie root filesystem in TKLDev, imports the configured root into
Docker, starts the normal systemd init path with first-boot credentials, and
runs `tests/v19.sh`. The retained report under
`~/.local/state/turnkey-v19-harness/runs/lighttpd-php-fastcgi/` records the
exact source and harness commits, archive and tree hashes, installed versions,
configured-root mode, application evidence, updater evidence, cleanup result,
and verdict.

## Updater check

`tests/v19.sh` runs `apt-get update` and checks eligible candidates for
`lighttpd`, `php-fpm`, `mariadb-server` and `adminer` with `apt-cache policy`.
It records the versions before the refresh and proves they are unchanged
afterward. A pass means APT accepted the signed Debian and TurnKey Trixie
metadata, each identity-defining package has an eligible candidate, and no
Bookworm source remains configured.

## Known limitation

The Docker acceptance path does not exercise the installer, kernel, bootloader,
or physical hardware. This appliance adds no behavior at those boundaries, so
the validated Core 19 baseline supplies the inherited evidence.
